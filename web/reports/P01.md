## Failures found and fixed during the phase

1. **The specimen leaked into normal production builds.** Found by `specimen-flag.test.mjs`: Vite does not fold a constant imported from another module. **Fix:** a build-time switch `__SPECIMEN_ENABLED__` set in `vite.config.ts`, which Vite replaces textually. Rerun: normal build contains no specimen code; the JS size is identical to P00.
2. **axe: 8 serious color-contrast violations** (English and French). **Cause:** the specimen drew non-text pairs (UI strokes, decorative rules, forbidden pairs) as text samples. **Fix:** those pairs are now shown as stroke samples; only text pairs get a text sample. Also fixed a moderate "landmark-unique" issue (two regions had the same name). Rerun: zero violations.
3. **Screenshot tests failed with "Test ended".** **Cause:** a bug in my test, which read the body of cached (304) font responses. **Fix:** only fresh 200 responses are measured. No product change.
4. **Visual bugs found by reviewing the screenshots myself:**
   - In the English and French pages, a sentence beginning with an Arabic channel name flipped to right-to-left, because I had used `dir="auto"`. **Fix:** the sentence follows the page direction and only the channel name is isolated with `<bdi>`. This is the pattern the screens should use.
   - In Arabic, token names and hex values were reordered (`color-paper--`, `f3efe6#`). **Fix:** code is always left-to-right.
   - Arabic swatch labels drifted toward the next swatch. **Fix:** labels now sit next to their own swatch.
   - At 360px, the type samples and the contrast table's pair column were squeezed. **Fix:** the type scale stacks below 480px, and the contrast table scrolls inside its own region.
     Each fix was followed by a full e2e rerun (28/28).

## Deviations from the plan text (for your approval)

1. **Specimen switch:** a Vite `define` (`__SPECIMEN_ENABLED__`) instead of reading `VITE_SPECIMEN` in `env.ts`. This was required for the specimen to be dropped from builds (failure 1). `VITE_SPECIMEN` is validated in `vite.config.ts`.
2. **jsx-a11y option:** `no-redundant-roles` allows `role="list"` on `<ul>`/`<ol>`. Lists without bullets lose their list semantics in Safari/VoiceOver unless the role is explicit. This is the option the rule provides for exactly this case.
3. **Fonts vendored into `public/fonts/`** (unhashed file names) so that `index.html` can preload them. Cache-busting on font updates is a P13 hosting concern.
4. **Specimen tables scroll inside a keyboard-focusable region at narrow widths.** The page itself never scrolls sideways (checked at 360px). The real stacked phone layout is the `ResponsiveRowList` in P02.
5. **`ArrowUp` / `ArrowDown` are solid triangles**, because their job is the movement glyph (`▲ 4`) described in `03` §2.
6. **The "new" icon is an eight-spoke burst.** The plan names it but does not describe it.
7. **`scripts/vendor-fonts.test.mjs` and `scripts/specimen-flag.test.mjs` run inside `npm run check`.** The second performs two quick builds and adds about 1 second.

## Known issues and limitations

- `check:contrast` detects a forbidden pair only when one CSS rule sets both the color and the background, not through inheritance. axe in later phases covers the rendered result.
- `check:css` is a small purpose-built reader, not a full CSS parser. It covers this project's style of CSS and its fixtures.
- The specimen uses the browser's default monospace font for token names (no mono font is shipped). This affects the specimen only.
